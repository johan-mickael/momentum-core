# Authentication and Authorization

## Authentication

All API endpoints (except `/auth/register`, `/auth/login`, and `/stripe/webhook`) require a JWT Bearer token.

**Login**:
```
POST /auth/login
{ "email": "...", "password": "..." }
→ 200 { "token": "<jwt>" }
```

The JWT is generated by `LexikJwtTokenGenerator` using the RSA keys at `config/jwt/`. The token carries the user's `email` as the identifier.

**JWT Firewall**: The `main` Symfony firewall is stateless. Each request is authenticated by extracting and validating the JWT. No session is created.

**Stripe Webhook firewall**: The `stripe_webhook` firewall matches `^/stripe/webhook` and has security disabled. Stripe's HMAC signature verification (handled in `StripePaymentWebhookHandler`) serves as the authentication mechanism for this endpoint.

## Role Hierarchy

```
ADMIN ⊃ STAFF ⊃ BUYER ⊃ USER
```

- `$role->isAdmin()` — true for ADMIN only
- `$role->isStaff()` — true for ADMIN and STAFF
- Buyers inherit BUYER and USER roles only

Roles are stored as enum values in the database and restored by `SymfonyUserProvider`.

## Authorization Architecture

Authorization is policy-based. The `AuthorizationService` holds a collection of `PolicyInterface` implementations (injected via a service tag). When `authorize($actor, $action, $subject)` is called:

1. The service iterates all registered policies
2. The first policy where `supports($subject)` returns true handles the decision
3. Returns `true` or `false`

Handlers throw a domain exception if authorization fails:

```php
if (!$this->authorizationService->authorize($actor, $action, new OrderContext($order))) {
    throw CancelOrderForbidden::create();
}
```

The `DomainExceptionListener` converts these to HTTP 403 responses.

## UserContext

Handlers receive a `UserContext` object extracted from the authenticated JWT:

```php
final class UserContext
{
    public function __construct(
        public readonly UserId $id,
        public readonly Role $role,
    ) {}
}
```

This is resolved by `HttpController::getUserContext()` → `SymfonySecurityUser::getUserContext()` → populated from the JWT payload at request time.

## Sensitive Endpoints

| Endpoint | Auth | Notes |
|---|---|---|
| `POST /stripe/webhook` | None (HMAC signature) | Stripe webhook; signature verified by `StripePaymentWebhookHandler` |
| `POST /auth/login` | None | Returns JWT |
| `POST /auth/register` | None | Creates USER |
| `POST /tickets/check-in` | JWT, STAFF+ | Staff-only; cannot be called by buyers |
| `POST /orders/{id}/refund` | JWT, owner or STAFF+ | Buyer can refund their own; staff can refund any |

## Password Security

Passwords are hashed using `SymfonyPasswordHasher` (wraps Symfony's native hasher, configured as `auto` in `security.yaml`). In test environments, bcrypt cost is set to 4 for performance.

The `PlainPassword` value object validates minimum length (8 characters) before hashing.
